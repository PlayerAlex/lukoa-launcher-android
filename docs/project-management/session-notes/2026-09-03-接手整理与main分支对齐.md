## 代码里值得重新评估的限制

扫了一遍 guard / policy 类文件，大部分限制（操作扩展前先停酒馆、备份恢复二次确认、路径不含控制字符等）是合理的安全措施。下面几项偏保守，是否放开由所有者决定：

1. **扩展只能从 `https://github.com/owner/repo` 安装和更新**（`TavernExtensionCommandCodec` 与 `lukoa-tavern.sh` 里的 `decodeRepositoryUrl` / `publicGithubRepositoryUrl` 双重限制）。启动器自己都提供 gh-proxy 镜像给主仓库，但扩展不能走镜像、也不能用 Gitee / GitLab / 自建仓库；已安装的非 GitHub 来源扩展会显示"扩展来源暂不支持检查"。这是最值得放开的一项，需要 App 侧、脚本侧和测试一起改。
2. 上传限制只能选 500MB / 1GB / 2GB（`TavernUploadLimitPolicy`），Node 内存只能选 2/4/6GB。可以考虑允许手填。
3. Git 源和 npm 源只接受 https（`TavernMirrorValidator`），局域网 http 镜像会被拒绝。
